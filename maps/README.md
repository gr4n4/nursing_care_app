# 지도와 보정값

여기 있는 것은 **빌드에 들어가지 않는다.** 화면에 쓰는 도면은
`assets/map/` 으로 따로 넣고, 이 폴더는 그 값이 어디서 나왔는지를 남긴다.

| 파일 | 무엇 |
|---|---|
| `ward_edit.pgm` · `.yaml` | 병동 4층 점유격자. 로봇이 길을 찾는 데 쓰는 지도 |
| `lab_4F.pgm` · `.yaml` | 연구소 4층 점유격자 (시험용) |
| `plan_ward_4f.png` | 병동 4층 비상대피도. **사람이 보는 그림** |
| `plan_lab_4f.png` | 연구소 4층 비상대피도 |
| `ward_map_fit.json` | 로봇 좌표(m) → 병동 도면 픽셀 변환 |

## 두 그림이 왜 따로인가

로봇은 **라이다가 본 것** 위에서 움직이고, 사람은 **보기 좋은 것** 위에서
본다. 점유격자에는 정수기도 세탁 카트도 찍혀 있고 유리벽은 비어 있다 —
흠이 아니라 그게 맞는 것이다. 센서가 보는 대로여야 로봇이 자기 위치를
찾는다. 대피도대로 유리벽을 반듯하게 막아 주면 로봇은 "지도엔 벽인데 왜
안 보이지" 하고 길을 잃는다.

그래서 둘을 두고, 좌표만 옮겨 준다.

## 보정값

    px = -4.280809·x + 20.552669·y + 1089.702
    py = -20.552669·x - 4.280809·y +  461.111

x, y 는 로봇이 `robot_state/current.pose` 에 올리는 미터 값이고, 결과는
`plan_ward_4f.png`(1672×941) 안의 픽셀이다. 1 m 가 20.99 px, 도면 1 px 가
4.8 cm.

### 어떻게 구했나

병동에 나가지 않고 책상에서 구했다. 점유격자는 `resolution`·`origin` 이
있어 픽셀을 로봇 좌표로 바로 바꿀 수 있으므로, 남은 일은 격자와 대피도를
포개는 것뿐이다. 격자의 **벽**(점유 칸)을 대피도의 **벽선** 위에 얹어
평균 거리가 가장 작아지는 회전·축척·이동을 찾았다(chamfer 정합).

방향이 중요하다. 대피도에는 모든 벽이 그려져 있지만 격자에는 라이다가
본 벽만 있다. 그래서 '격자 → 대피도' 로 맞춘다. 반대로 하면 짝이 없는
벽이 많아 축척이 무너진다.

**거울상이 필요하다**(`mirror`). 닮음변환만으로는 안 맞고, 뒤집기를 넣어야
돌출부와 간호사실 상자가 제자리에 온다. 위 여섯 계수에는 이미 들어 있다.

연구소는 맞추지 않았다. 유리벽이 안 잡혀 벽 자료가 병동의 1/5 뿐이라
정합이 수렴하지 않는다. 필요도 없다 — 로봇 쪽 설정에서 연구소는
`poseOnAppMap: false` 라, 애초에 점을 그리지 않는다.

## ⚠️ 로봇이 지도를 다시 만들면 이 값은 깨진다

SLAM 을 다시 돌리면 `origin` 이 바뀌고, 그러면 위 계수가 통째로
어긋난다. 점이 엉뚱한 데 찍히기 시작하면 제일 먼저 이것을 의심할 것.
`.pgm` 과 `.yaml` 을 새로 받아 다시 맞추면 된다.

그래서 계수를 코드에 박지 않고 Firestore `settings/ward_map` 에 둔다.
앱을 다시 배포하지 않고 고칠 수 있어야 한다.
